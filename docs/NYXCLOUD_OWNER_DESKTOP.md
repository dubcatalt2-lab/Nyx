# NyxCloud private desktop

NyxCloud is the persistent local QEMU VM on the Windows PC. It is available through Nyx's owner dashboard only for Firebase UID `3158eOj4ATMzkoC1PAm8H7TXc2R2`. Staff/owner role labels on other UIDs grant no access.

The dashboard requests a ten-minute HttpOnly Secure SameSite=Strict page session, then opens `/apps/nyxcloud/`. The viewer uses Firebase bearer verification and a one-use 30-second WebSocket ticket, bound to the page session's token. All Firebase checks include revocation. The viewer renews its page session/token every minute over authenticated HTTP while the stream separately rechecks revocation. A temporary account-service outage gets at most two minutes of grace; explicit revocation is immediate at the next check. Streams apply backpressure, send heartbeats and automatically retry temporary disconnects. Only revoked/invalid access stops retrying; token expiry requests fresh authorization. Other users receive 404, including for viewer assets. The viewer has fullscreen, disconnect and reconnect controls. Local tests use mock authentication; production always uses the real Firebase Admin verifier.

QEMU listens on Windows loopback `127.0.0.1:5990`, with a privately generated VNC password. Its Node supervisor starts `nyxcloud-host/tunnel.mjs`, which maintains an encrypted outbound SSH reverse tunnel to VPS loopback `127.0.0.1:15990`. The dedicated restricted SSH identity cannot run shell commands and is permitted to listen only at that address/port. The backend connects only to this fixed loopback upstream; clients cannot choose an address. No public VNC port, ngrok instance, or VM launch/control API is created. The existing physical-PC remote desktop is separate.

Server configuration: `NYXCLOUD_VNC_PORT=15990`, `NYXCLOUD_VNC_PASSWORD` in protected `/etc/nyx/nyx.env`. `deploy/setup-nyxcloud-tunnel.py` takes public SSH key and VNC password JSON over stdin as root; never put its input in logs or source. Local private files live under `%LOCALAPPDATA%/NyxCloud`: `cloud-remote.json`, `cloud-tunnel-key`, and its `.pub` file. `run.mjs` enables VNC, sets its password via QMP, and starts/closes the tunnel with the VM. Reopen using `Start-nyxCloud.cmd`; this is a local running VM, not an always-on VPS VM. The Windows host must remain powered on and awake.

Validation: `node scripts/test-nyxcloud-desktop.mjs` checks exact UID, protected page access, origins, ticket replay, stream data/input, active revocation and private upstream. `NYXCLOUD_LOCAL_CONFIG=<private local config> node scripts/test-nyxcloud-browser.mjs` verifies real QEMU pixels and disconnect/reconnect using a loopback test server and mocked auth, without sending guest keyboard/mouse input. The normal test never reads local secrets. Live unauthenticated checks should verify `/api/nyxcloud/access`, `/apps/nyxcloud/` and `/apps/nyxcloud/app.js` return 404.

The user authorized the local restart on 2026-09-30. It shut down cleanly and reopened with the update. A live browser check displayed the desktop at 2560x1461. Neither Windows input nor clipboard automation is used.

Disconnect diagnostics: `NyxCloud session` records only close code/cause/duration in the service journal; no token/password/frame content. `scripts/test-desktop-resilience.mjs` covers lossless backpressure, 70 simulated minutes of token renewal, account-service outages and revocation. Set `NYXCLOUD_SOAK_SECONDS=120` on the live browser test for a sustained stream and forced reconnect check. The Windows bridge updater still requires administrator rights; server deployment does not modify the installed protected service. Closing QEMU ends the VM and its SSH tunnel; a running viewer cannot restart it remotely.
