## Architecture

Nyx is primarily a vanilla HTML, CSS, and JavaScript application, not React or another component framework.

- `index.html`: main application shell and entry markup
- `script.js`: main client runtime; browser tabs, navigation, settings, themes, profiles, proxy selection, games entry points, and many UI flows
- `styles.css` and `css/`: base styles plus feature-specific presentation layers
- `startup-studyhub.html` and `startup.js`: startup/onboarding experience
- `ai.html`, `js/ai-workspace.js`, `css/ai-workspace.css`: AI workspace
- `js/owner-dashboard.js`, `css/owner-dashboard.css`, `css/owner-dashboard-polish.css`: Owner Dashboard
- `server.js`: Express 5 application and HTTP/API routes
- `wisp-server.js`: standalone Wisp WebSocket service used by Railway
- `uv/`, `uv.sw.js`, `uv.config.js`: Ultraviolet proxy runtime
- `scramjet/`, `scramjet.sw.js`: Scramjet proxy runtime
- `scramjet-v1/`, `scramjet-v1.sw.js`: separately scoped legacy Scramjet v1 runtime, loaded only when the user selects it; its root worker must be included in the static production bundle.
- `baremux/`, `epoxy/`, `libcurl/`, `assets/transports/`: BareMux, Epoxy, and upstream Libcurl Raw transports with Nyx-owned header-shape adapters for Scramjet and BareMux
- `assets/games/`: GAMES UI, manifest, LuminSDK headless-catalog adapter, game launcher, and fallback behavior
- `apps/chat/`: account-only community chat client and responsive Discord-inspired presentation
- `assets/ugs/`, `assets/gn-math/`, and `assets/gms-games/`: repository-backed game sources and players. GN Math keeps a repository snapshot generated by `npm run sync:gn-math` from the current `genizy/npm` catalog; its game HTML and covers resolve through Nyx's fixed-target routes to the upstream `freebuisness/html` and `freebuisness/covers` repositories. Remote GN Math documents run inside a nested opaque-origin sandbox without popup or top-navigation privileges; the fixed-target routes remain CORS-readable so sandboxed fetch, module, WebAssembly, and worker resources work without granting games access to Nyx's document. The former Seraph snapshot, runners, and server relays are removed.
- `netlify/functions/api.mjs`: wraps the Express app with `serverless-http`
- `scripts/build-netlify.mjs`: produces generated `dist/` output and runtime configuration
- `firestore.rules`: Firestore access rules; these are not deployed by Netlify

Client preferences and much local UI state use browser storage. Cross-device account, profile, role, subscription, activity, and audit state use Firebase Authentication, Firebase Admin, and Firestore through server routes.

## Main Product Areas to Preserve

- Browser shell, tabs, navigation, address bar, downloads, popup protection, and developer console
- Recognized crawler, link-preview, and non-browser automation user agents receive a server-rendered, non-interactive Student Learning Portal decoy for HTML document routes. The decoy contains no Nyx scripts, is marked `noindex`/`nofollow`, and is served with browser/CDN no-store headers. API, health, Wisp, Socket.IO, robots, sitemap, manifest, and static-asset routes bypass it, as do normal browser user agents. This is a casual-discovery deterrent rather than an authorization boundary because user-agent strings can be spoofed; credentials and sensitive logic must remain server-side.
- Smartwatch layout for short, narrow viewports, including reachable home actions and compact browser controls
- User-selected proxy engine and transport
- Themes and custom recoloring
- Homepage shortcuts, effects, profile/account controls, and search/course entry
- Searches submitted while the preserved Chat app tab is active open in a separate browser tab and select that result tab immediately, leaving Chat connected in the background.
- Browser-shell history records Scramjet URL changes as source URLs. Back/Forward restore those source entries, while a tab's initial blank entry returns to the Nyx new-tab surface instead of being sent through a proxy engine.
- Navigating one new tab must not prune the user's other blank tabs. Blank tabs remain independent until the user explicitly closes or reuses them.
- The redesigned homepage uses the reduced-motion-aware React Bits Beams canvas with compact hero geometry across themes. Theme choices tint the Beams preset and interaction accents while normal text, navigation icons, fields, and translucent panels retain a readable neutral hierarchy. The same balance applies to the generated Apps and Settings workspaces. The particle wordmark owns the visible **NYX** title after its canvas initializes; theme text rules must not expose the solid fallback letters underneath it. **Home design** in Settings can restore the maintained original homepage, which disables redesign-only styles and behavior rather than leaving parts of the new shell behind. The browser tab controls must remain reachable above Settings so that Settings never traps navigation. The redesigned homepage and Apps workspace must fit without horizontal or vertical clipping down to a 320-pixel-wide viewport. The Apps shortcut opens the complete Apps tab directly; the retired hidden app-launcher drawer and its duplicate catalog markup must not be restored.
- In compact **Tab bar** mode, Escape closes an open tab drawer and restores focus to the visible tab control. Keep this behavior independent of other overlays that may also consume Escape.
- The redesigned homepage background is the licensed React Bits Beams shader. It spans the viewport without opaque document layers or legacy constellation canvases above it. The maintained geometry uses the React Bits showcase proportions (3 width, 30 height, 20 strips, zero spacing, 100 height segments) and its delta-time animation; equivalent orthographic framing prevents independently displaced shared edges from opening moving cracks. Each built-in theme selects a corresponding Beams tint immediately; an explicitly chosen wallpaper may override that automatic mapping. Medium/minimum performance and reduced-motion modes keep a static rendered frame rather than restoring the retired star field. The sidebar and address toolbar use the opium-style house glyph for Home, while the equal four-square glyph is reserved for Apps.
- The redesigned homepage replaces the former centered dashboard with a small live latency bubble. It measures the browser-to-Nyx round trip through cache-bypassed same-origin `/healthz` requests, calibrates from three initial probes, then updates a five-sample rolling median every second while the page is visible. Hidden pages skip probes and an in-flight guard prevents slow requests from stacking. This rejects connection-warmup and event-loop outliers while retaining a current quality signal. The bubble shows the stabilized milliseconds with a quality color and reports **Offline** when the health route fails, times out, or the browser loses connectivity. Hovering or keyboard-focusing it reveals a 24-sample live line chart, latest/stable/range measurements, browser connectivity, and the health route's Nyx, Wisp, and Chat states. The separate authenticated Owner Dashboard remains unchanged.
- The redesigned homepage keeps compact bottom-right text links for Link Checker, Link Generator, and Terms of Service. They use the normal managed-tab/internal-page routes and move above the latency bubble on narrow screens.
- Legacy Aether navigation is still forced through Nyx's contained popup bridge when opened manually, even when general popup protection is disabled. Nyx also quarantines Aether's known escaped download-reminder overlay and cleans up any remainder when users switch or close tabs, so third-party ad UI cannot replace or cover the Nyx shell.
- Pirate Cove installs the same enabled Popup Protection ad and popup guards into its player iframe and every accessible nested game iframe, including dynamically added descendants. Managed Scramjet game frames receive the ad-block and minimal popup-guard plugins at HTML rewrite time; Ultraviolet and same-origin runner frames are protected on navigation and load. The guard removes known game-ad resources and containers without removing the game surface, and remains governed by the existing `nyx.popupProtection` preference.
- Profile customization, animated avatars and banners, decorations, effects, badges, roles, status, and profile directory
- Settings and onboarding. First-run customization is controlled only by the explicit `nyx.setupComplete` marker; normal startup defaults must not be mistaken for proof that onboarding was completed. The wizard, Terms acceptance gate/page, and versioned update dialog use the same translucent Beams-visible glass surfaces, compact rounded geometry, theme-relative accents, and high-contrast action text as the maintained shell. Email-backed accounts still require Firebase-confirmed verification before cloud-save eligibility; do not infer that a syntactically plausible or disposable-looking address is real, and do not weaken verification based on address text.
- AI workspace, model selection, conversations, temporary chats, image attachments, and API integration
- Owner Dashboard, role permissions, subscriptions, premium access, profiles, activity, and audit records
- Account-only community chat channels, voice rooms, message history, online member presentation, unread state, send limits, and author/moderator deletion. The channel rail is one continuous scroll surface: text channels, voice rooms, their active voice controls, direct messages, and the dismissible safety reminder flow together instead of creating separate nested scroll areas; the signed-in account remains anchored below that rail. Desktop and mobile drawer layouts share this structure.
- Shared homepage/guest presence is kept in the active OVH Node process, including the stable guest label and authenticated account UID when a valid bearer token is present; it does not consume Firestore reads or writes
- Signed-in activity heartbeats run every five minutes while visible; they refresh activity state, but rewrite the administration IP only when it changes or its recorded timestamp is at least 24 hours old
- About Nyx and its user-directed changelog
- Pirate Cove search, sorting, pagination, remote catalogs, fallbacks, and full-screen player
- Single-file export/download behavior; the Settings action fetches the current launcher into a completed browser Blob before saving `Nyx-Download.html`, `/download/nyx-singlefile.html` remains a direct attachment route, and opening the downloaded file preserves its local `file:///.../Nyx-Download.html` address while embedding the canonical OVH-hosted `https://nyxlearning.org/` release. The launcher includes the complete online Nyx application, including Pirate Cove, but requires an internet connection and is not a fully offline site bundle.

Nyx AI obtains its selectable catalog from the provider without exposing the server key. Nocturne's `/api/ai/config` catalog is session-based and returns only the anonymous model to API-key requests, so Nyx validates its known and explicitly configured candidate IDs with no-prompt authorization checks and caches the verified result for one hour. Those checks do not generate a completion or consume model output tokens. `NYX_AI_MODEL_IDS` may add newly issued provider model IDs to the candidate set without a code release. Do not restore unavailable models merely because they remain in an old static list. Assistant replies render Markdown tables, tab-separated tables, and standard `\(...\)` / `\[...\]` LaTeX with the locally served KaTeX runtime so managed devices do not depend on a third-party CDN.
Nocturne's Claude Opus 4.8 endpoint currently rejects native image content even though it accepts text. Claude must not be advertised as provider-native vision unless the provider later reports that capability. Nyx's server-local vision pass makes attachments usable with the selected text model without silently switching to `nocturne:flash`; the selected and saved model therefore remain authoritative.

Users may optionally supply a personal Nocturne API key, a Nyx-issued `nyx_...` gateway key, or a key plus public HTTPS OpenAI-compatible base URL through the key control in the Nyx AI header. Ofox has a first-party convenience preset for `https://api.ofox.ai/v1`; other compatible providers use their documented `/models` and `/chat/completions` routes. Personal keys and custom base URLs stay in browser session storage by default, or local storage only after the user explicitly selects **Remember on this device**; they are never written to Firebase, source, server logs, or an API response. The browser sends them only to Nyx's same-origin AI routes. The server rejects credentials, query strings, fragments, literal IPs, local/internal hostnames, non-HTTPS origins, nonstandard ports, redirects, and DNS answers in private, loopback, link-local, multicast, documentation, or reserved address space before contacting a custom provider. A Nyx key is validated and spent through the server-only Groq gateway, which discovers its available Groq models server-side; a Nocturne key remains a direct Nocturne credential. Removing it returns that browser to Nyx's shared server key. An invalid personal key must never silently fall back to the shared credential. If a model emits an explicit `<think>…</think>` block, Nyx renders it as a collapsed native disclosure above the answer, strips it from copied text and subsequent chat history, and suppresses incomplete tags while streaming. The standard chat limiter stays IP-scoped for anonymous traffic; signed-in accounts are isolated from other users on the same IP, and Premium/Owner accounts bypass its daily request ceiling while retaining short burst and concurrent-request safeguards. Navy model catalogs are filtered server-side to chat-capable entries without Navy's `premium:true` marker, so a free Navy account cannot select an upgrade-only model through the picker or request route. Nyx's shared Navy provider requires sign-in and uses a separate Firestore-backed generated-token allowance per UTC day: 1,500 for regular members, 5,000 for Premium, and unlimited for Owner; personal Navy keys remain subject to the user’s own Navy plan rather than Nyx’s shared-provider allowance.

Claude Opus 4.8 is withheld from the model catalog and rejected server-side unless the request carries a valid active Premium account token; this remains true when the browser supplies a personal AI key. The embedded `/ai.html` workspace requests that token only from its exact containing Nyx tab through the scoped account-token bridge, so an Owner returns to the complete shared catalog after removing a personal key. Premium accounts receive 50,000 Firestore-backed AI credits per UTC day for Claude Opus, with each generated token consuming one credit. The configured Owner role can use every provider-available model, including Opus, without that daily cap. Keep this entitlement and reservation logic server-side; the client picker is only a convenience layer.

The AI workspace includes local chat search, Off/Normal/Extended response-depth controls, the current model summary, per-browser estimated token/response totals, and user-controlled screen sharing. Starting a share uses the browser's native display picker, never requests audio, shows a live preview with an explicit Stop action, and uploads no background stream: each Send captures and attaches only the current bounded JPEG frame. The share remains active for follow-up questions until the user stops it, clears the conversation, closes the page, or the browser ends the display track. Static image/text attachments and screen sharing replace one another to keep each request unambiguous. Its document canvas is transparent over the active Beams wallpaper; fixed neutral glass surfaces, text, bubbles, and controls preserve readability while the selected theme color remains an interaction accent. Response depth is validated server-side and maps to Nocturne's native `level` and `reasoning_effort` fields plus bounded output guidance; it does not reveal private chain-of-thought. Usage totals are approximate character-based estimates kept only in browser storage because Nocturne's streaming response does not expose authoritative billing usage. Nocturne does not publish a complete API-key model-list endpoint, so the per-key catalog is the intersection of Nyx's current candidate IDs and no-prompt authorization probes; keep current Claude candidates in that verified set rather than exposing them unconditionally.

AI image attachments use a bounded server-side vision pass because Nocturne's API-key endpoint rejects image payloads and its working image route requires a separate interactive Nocturne login. The browser preserves supported images that already fit the request limit and otherwise downsizes/compresses them before sending them only to Nyx's same-origin AI route. When the server-only Groq credential exposes a current Qwen vision model, Nyx sends the in-memory image to that Groq vision endpoint for detailed scene reading and OCR, treats all image text as untrusted data, and supplies only the resulting textual evidence to the user's selected chat model; `NYX_GROQ_VISION_MODEL` may override the preferred available vision model. Every workspace provider path, including Nyx-issued keys and shared Groq, receives this evidence instead of silently dropping the image. If Groq vision is missing or temporarily unavailable, Nyx falls back to the quantized `Xenova/vit-gpt2-image-captioning` worker. That local analysis runs in a short-lived child process with ONNX Runtime's CPU arena and memory-pattern allocator disabled, sequential one-thread execution, and a three-minute deadline; this returns native allocations to the operating system after every request and prevents repeated requests from accumulating model memory in the web process. The real `sam.webp` regression identified the white house in a 16-second OVH probe capped at 1.2 GB, with systemd reporting a 1 GB peak; the coordinating process stayed near 49 MB in the local isolation check. User image bytes are never written to disk, placed in source, exposed through a public capability route, sent to the selected text-chat provider, or logged; only the configured server-side Groq vision endpoint may receive the transient image bytes. Deployment warms the fallback model cache through the same isolated worker at `/var/lib/nyx/vision-models`; the cache contains model files only and must remain writable by the `nyx` service. The model picker preserves the user's selected model. Temporary catalog gaps use an available fallback without overwriting the saved model preference, so the preferred model is restored when it returns. Stream decoding flushes split UTF-8 data correctly, normalizes structured provider deltas, and replaces a detected symbol-corrupted response with one low-temperature retry or a readable failure instead of retaining gibberish.

Up to eight named personal-provider profiles can coexist and be activated without re-pasting credentials, so Ofox, TokenMix, and other compatible accounts do not overwrite one another. Providers other than the Ofox preset use the exact OpenAI-compatible base URL shown in their own documentation or sample code; Nyx must not guess provider endpoints. The owner may alternatively expose Ofox and TokenMix as shared provider-picker entries with server-only `NYX_OFOX_*` and `NYX_TOKENMIX_*` environment values; those global credentials must never be returned to the browser.

## Durable Product Instructions

- AI screen sharing sends one fresh bounded frame per message rather than a continuous video stream. Preserve the server-validated screen-frame marker through client image preparation, server vision analysis, and the selected model prompt so an attached shared frame is never misreported as absent or manually uploaded. Multiline `\[ ... \]` and `$$ ... $$` blocks must be collected before KaTeX rendering so display equations, fractions, arrows, and boxed answers do not expose raw delimiters.
- The AI Markdown block classifier must treat a display-math opener as a block boundary even when it immediately follows prose without a blank line, accept provider-double-escaped fences, and render a final unfinished fence as math instead of leaking delimiter text.
- NyxTube video results retain a validated YouTube channel ID and receive cached channel artwork through a bounded `channels.list` lookup. The watch creator avatar and name open the exact `youtube.com/channel/{id}` destination through Nyx's managed browser navigation; an optional artwork failure must retain the initial fallback and must not break the video catalog.
- Preserve functionality before changing presentation.
- Diagnose the actual cause of a regression; do not keep stacking speculative CSS, proxy overrides, cache resets, or host-specific fixes.
- The user's explicit proxy engine and transport choice should remain authoritative. Do not silently force a different engine for a site unless the user asks for that policy. Auto transport now sends the upstream Libcurl client to either Scramjet or BareMux as `libcurlRaw` for every external site and uses Epoxy/Wisp only as recovery transports. Nyx's local adapters normalize only the two engines' incompatible request/response header shapes; they do not replace Libcurl or fetch executable proxy code from another deployment. Legacy saved `libcurl` preferences migrate to `libcurlRaw`; fixed Epoxy or Wisp choices remain fixed.
- Browser settings use the recognizable user-facing engine labels **Auto**, **Scramjet v2**, **Scramjet v1**, **Ultraviolet**, and **Iframe**, plus transport labels **Auto**, **Epoxy**, **Wisp**, and **Libcurl**. Selecting v1 affects only proxy navigation and game-frame routing; it must not modify home, icons, labels, or shared CSS. Keep the upstream package names, route paths, storage values, globals, and protocol identifiers unchanged so updates, service-worker scopes, attribution, and compatibility checks continue to work.
- Popup Protection preserves a proxied page's `window.open(url, "_self")` as same-tab navigation while continuing to contain real popup targets. This is required by ordinary Chromium flows and NVIDIA's same-tab OAuth handoff. Scramjet also supplies NVIDIA's auth family with the Storage Access API surface its official hidden login-hints frame requires; the compatibility is host-scoped and does not relax the Nyx iframe sandbox for unrelated sites.
- Scramjet controller frames are tied to a particular service-worker instance. After registering or updating that worker, wait for the requested version to become active and reconnect the existing controller's message port to that exact worker before routing a frame; checking only that any older worker is active recreates the **Scramjet route missed** race.
- External browser tabs use private, per-tab proxy cookie sessions. Scramjet creates a separate controller and in-memory cookie jar for each Nyx tab, scopes service-worker cookie synchronization to that controller, disables saved-cookie persistence, and clears the jar when the tab or browser window closes. Ultraviolet encodes a random tab session in the `/service/` path, stores cookies in a separate IndexedDB database for that session, and clears its cookie store on tab or page close. Proxied documents also deny the precise Geolocation API, and browser iframes carry a geolocation-denying Permissions Policy. This isolation does not change Nyx account/session storage, prevent a destination from inferring an approximate location from the proxy/VPS egress IP, or provide VPN-level anonymity; an abrupt browser/process crash can also prevent best-effort close cleanup, although the random abandoned session is not reused.
- Smartwatch-specific layout is limited to viewports no larger than 480px wide and 520px tall. It keeps Back, Reload, Home, the address field, and Menu visible; Forward, Bookmark, and Weather remain available outside that watch breakpoint.
- Dense workspaces must account for ChromeOS display scaling: Link Checker and Nyx AI collapse their desktop sidebars at 1100px so filters, model controls, tables, and dropdowns retain the full content width. Larger laptop and desktop viewports keep the persistent sidebars. The main browser shell also has a viewport-driven short-laptop layout for 481-1100px-wide screens at 650px height or less; it compacts the homepage, account menu, weather report, and settings controls without changing the separate watch layout.
- When Link Checker, Nyx Chat, or API Keys runs inside a Nyx tab, it obtains a fresh Firebase ID token from the authenticated same-origin parent through the narrowly scoped `nyx:account-token-request` bridge. The parent validates the requesting tab as an exact allowlisted first-party utility path before replying. This avoids loading a second Firebase copy from Google's CDN, which managed Chromebooks can replace with an HTML block page. Direct standalone app pages retain the Firebase module fallback.
- Nyx Chat uses the same narrowly scoped parent token bridge, with the parent accepting only the exact `/apps/chat/` and `/apps/link-checker/` paths. Chat is unavailable to guests. Staff-managed community channels and two-participant private DMs read and write through authenticated `/api/chat/*` routes; direct browser access to `nyxChatChannels`, `nyxChatConversations`, `nyxChatAttachments`, `nyxCaffeineGifts`, `nyxChatConfiguration`, and `nyxChatMutes` remains denied by Firestore rules. Owner, Co-owner, Admin, and Manager roles can create, rename, remove, and apply minimum-role restrictions to text or voice channels through the server API; at least one channel of each kind is retained. The default **Staff Room** requires Moderator or above, and server-side scope checks protect its messages, attachments, activity, presence, and voice signaling. Private-message APIs and attachment downloads verify that the requester is a conversation participant, and public-channel moderator powers do not grant access to private DMs. Scope resolution must test explicit channel and conversation identifiers without allowing an absent channel to default to `general`; this keeps DM reads, sends, reactions, deletes, and attachment authorization isolated from public chat. Messages support plain text up to 1,000 characters, up to three allowlisted 8 MB attachments with an 8 MB combined limit for every role, and the fixed reaction palette. Allowlisted attachments include the existing image, PDF, text, and Office formats plus common MP3/M4A/OGG/WAV/WebM audio and MP4/MOV/OGG/WebM video; media renders with authenticated in-chat controls and unsafe active web/executable formats remain blocked. New attachments upload in bounded Firestore chunks and are served only through authenticated routes, and files or images pasted into the composer with Ctrl+V follow the same validation. Historical streamed Owner attachments remain readable and deletable, but the large-upload endpoints reject every new file above 8 MB. Authors can delete their own messages, while Moderator-or-higher roles can remove others' public-channel messages. Right-clicking a message opens a Nyx-styled context menu for Reply, the fixed quick-reaction palette, Copy text, Copy message ID, and Delete when the same author/moderator rule allows it. Member mentions and slash commands autocomplete in the composer; applicable commands include private-message, Caffeine gift, voice controls, channel lock/unlock, account disable/IP-ban/re-enable, timed chat mute/unmute, presence/ping, and harmless text transforms. `/mute @person` asks for a duration from one minute through four weeks and a required reason; the server persists and enforces that mute across public channels and DMs, prevents self/peer/higher-rank moderation, and records mute/unmute audit events. Nyx may persist multiple Owner roles, but the configured Founder Owner remains the sole hierarchy override: only the Founder can promote or demote secondary Owners, moderate another Owner, manage custom roles, or publish the Founder profile, and no account can target the configured Founder itself. Secondary Owners retain normal Owner operational permissions but cannot manage the Founder or a peer Owner. Microphone commands remain separate as `/micmute` and `/micunmute`. Privileged slash commands reuse authenticated server APIs, so client-side menu visibility is never the authorization boundary. Only Moderator-or-higher roles may send `@everyone`. On the active OVH server, Firebase-authenticated Socket.IO rooms deliver persisted messages, DMs, reactions, deletes, presence, Caffeine, membership, and channel changes immediately to authorized viewers without a Firestore query per connected browser. The in-memory revision feed remains as a once-per-minute consistency fallback while sockets are healthy and resumes its faster recovery cycle if the socket cannot connect. Member/channel data use bounded ten-minute server caches and identities use a bounded fifteen-minute cache, while a ten-minute bootstrap refresh preserves eventual consistency; administrative/profile writes invalidate those caches immediately. Every new incoming channel message or DM sends one narrowly validated same-origin notification to the parent Nyx tab, excluding the viewer's own posts and deduplicating Socket.IO/polling delivery. The parent plays the louder two-tone ping after browser audio is unlocked and displays a red unread dot until that tab is activated; standalone Chat retains the same local sound. Clicking a chat member asks the same-origin Nyx parent to open that account in the existing full public-profile viewer.
- Chat caches its Firebase ID token for the safe lifetime of the token instead of requesting one for every API call. Plain-text sends clear and restore focus immediately, render an optimistic **Sending...** row, and serialize writes in the background so members can type consecutive messages without duplicate or out-of-order local state. The server resolves message identity and mute state concurrently. Attachment and command sends keep their stricter locked flow. Clicking an image attachment opens a contained, dismissible full-screen preview without exposing its authenticated URL outside Chat.
- Chat member lists are grouped by canonical Nyx role rank (Owner through Member); each role group places online accounts before offline accounts, then sorts by display name. Every non-Member role name uses its canonical role-color pair for the same layered glow/highlight treatment everywhere Chat renders that identity; Member names stay neutral, and this visual treatment never replaces server-side role authorization. Moderator-or-higher roles can open **Search history** from the member sidebar or use the shield beside an account in Owner Dashboard to review that account's retained searches. Every explicit search made through Nyx while an account is signed in is sent to the authenticated server route and retained in `nyxSearchHistory` for 30 days; recording waits for Firebase's persisted account restoration, retries once after an expired-token rejection, and the first confirmed write on a browser displays a disclosure toast. The conservative classifier remains as a server-generated label so policy-matching searches are highlighted, but normal searches are retained too. Records contain the search text, classification, account identity, role, and timestamp; they do not contain IP addresses, destination URLs, clicked results, or search-engine metadata. Direct Firestore access is denied, and results are exposed only through the authenticated Moderator-or-higher API. The configured Founder can review all retained searches, while every non-founder reviewer receives a server-filtered result that excludes other Owner accounts; a secondary Owner may still review their own history. The dashboard also hides Owner shields from staff who cannot manage that account. Legacy flagged-search API paths remain aliases during the cached-client transition.
- The Chat slash-command registry contains 87 built-in commands: the existing messaging, voice, Caffeine, information, and server-authorized staff actions plus member-safe utilities for text formatting, encoding, random choices, calculations, timers, dates/time zones, channel/member summaries, status messages, and welcomes. `/warn @person reason` sends an audited official warning through a private conversation, `/demote @person` moves an eligible target down one built-in role through the same server-enforced hierarchy used by the Owner Dashboard, and `/purge [1-100]` lets Moderator-or-higher roles remove the newest public-channel messages after confirmation. Purges are authorized and audited on the server, remove bound attachment data, and broadcast one scoped realtime update. The Owner can additionally create, edit, alias, and remove up to 50 shared response commands through the command dialog. Those commands are stored in the server-managed Chat configuration, broadcast through the existing configuration revision, and support plain-text `{user}`, `{handle}`, `{channel}`, `{args}`, and numbered argument templates without executing arbitrary code. Built-in names stay reserved. All commands remain discoverable through `/help` and composer autocomplete; generated messages are subject to the same 1,000-character ceiling as manually typed messages.
- **Caffeine** is the chat-facing name for the existing Nyx Premium entitlement. Owner and Co-owner roles always receive Caffeine and may create unlimited distinct gifts; directly assigned Premium or Trial accounts may send one Caffeine gift for the current subscription grant. The recipient sees an in-chat acceptance prompt; accepting atomically marks that individual gift accepted and grants the existing Premium subscription status. Gift-derived Premium cannot be gifted again, an active recipient cannot accept another gift, pending gifts expire after seven days, and Owner Dashboard subscription assignments rotate a normal subscription gift grant only when beginning a new Premium period rather than on every save. An unlimited role gift is valid only while its sender remains Owner or Co-owner. There is no separate payment processor or checkout record in this repository, so “purchased” currently means Premium or Trial assigned through the existing administration flow.
- Nyx Chat voice rooms are account-only and use the server-managed voice-channel list, initially **Lounge**, **Gaming**, and **Study Room**. Audio and optional screen-share video travel between browsers with WebRTC and are never recorded or stored by Nyx; the persistent OVH Node process keeps only authenticated room presence and 60-second offer/answer/ICE signaling in memory. Screen sharing is available only after joining voice, uses the browser's native display picker, has an explicit start/stop control, and automatically cleans up when the browser ends capture or the user leaves voice. Authenticated Socket.IO delivers voice membership changes and offer/answer/ICE signals immediately, while the voice-state route polls only as recovery. Explicit leave/disconnect ends an active call; a 24-hour stale-presence cleanup only removes callers whose browser disappeared without sending leave. Each room is limited to eight participants to bound browser CPU/network use. The client provides join/leave, microphone mute, deafen, screen sharing, live participant lists, and profile handoff. Voice capture uses echo cancellation, noise suppression, and microphone automatic gain control; received audio uses gain plus compression, prefers Opus with in-band FEC and DTX disabled, requests a modest receive jitter buffer, prioritizes the audio sender, and restarts ICE after sustained disconnection. Nyx's internal tab switcher must leave Chat audio running instead of pausing its media elements. Public STUN remains the fallback. - Chat `/ban` and `/ipban` use the same Owner Dashboard mutation route and require or prompt for the member-facing message. Permission and hierarchy checks remain server-authoritative.

## Custom Roles and Profile Presentation

- The configured Founder Owner is the only account allowed to create, edit, delete, or assign custom roles and the only account allowed to assign the built-in Owner role. Definitions live in the server-only `nyxCustomRoles` Firestore collection and contain a stable ID, a display label up to 64 characters including formatting codes, color, built-in hierarchy placement, and a validated list of existing Nyx permissions. Owner Dashboard presents these definitions as a compact list and expands only the role currently being edited. The dashboard accepts either `#RRGGBB` or Minecraft `&0`–`&f` codes for the role color and normalizes them to a safe hex value. Custom roles cannot create another Owner or invent arbitrary permission names.
- Assigning a custom role retains its built-in placement in `nyxUserAdministration.role`, records the custom role ID, and remembers the prior built-in role so removal can restore it. Direct built-in role changes clear any custom assignment. Owner Dashboard and Chat show the custom label/color while security comparisons continue using the placement rank.
- Chat exposes `/roles`, Founder Owner-only `/roleadd` and `/roleremove`, plus `/userinfo`, `/avatar`, `/channelinfo`, `/poll`, and `/timestamp`. Command visibility is only a UI aid; every privileged mutation is re-authorized by the server.
- Chat expands a local 1,948-entry standard Unicode emoji catalog and its aliases on the actual send path and shows matching suggestions as the member types. It includes `:cold_face:` → 🥶 and `:skull_and_crossbones:` → ☠️ while retaining distinct names such as `:cold_sweat:` → 😰. Nyx does not yet support server-specific custom emoji; unknown shortcodes remain unchanged.
- Display names and Chat message bodies may contain Minecraft-style `&` formatting codes for the 16 Bedrock colors plus magic, bold, italic, underline, strikethrough, and reset. Message formatting is rendered through safe DOM nodes and composes with clickable mentions; formatting is presentation-only, while canonical account usernames/handles remain plain and continue to control login, mentions, and uniqueness.
- Profile cosmetics are being narrowed to simple, readable motifs: a blooming rose vine around the profile edge and candlelight around the avatar. Saved IDs from both earlier generic cosmetics and the retired signature-scene collection migrate to these replacements, identity content remains unobscured, and animations become static under reduced-motion preferences.
- The compact homepage account menu intentionally suppresses profile effects and avatar decorations. It remains a clean navigation surface while full profile cards and the editor preview remain the cosmetic preview surfaces.
- Legacy profiles whose avatars are still stored as inline image data use the same-origin `/api/profile-avatar/:uid` bridge in compact member lists. This keeps large image data out of Owner Dashboard and Chat JSON responses while allowing the saved avatar to render; newer chunked profile-media URLs continue to load directly.

## Global App Catalog

- User-facing product copy describes what a feature does and its actionable state. Keep this mode opt-in so Link Checker and other utility pages are not restyled accidentally.
- **JSDelivr Publisher** is a first-party utility at `/apps/jsdelivr-publisher/`, appears in the Link Generator header as **Jsdelivr Links**, and is a built-in Apps-catalog entry. It accepts one bounded SVG and publishes randomized copies to a selected public GitHub repository or newly created public repositories, with at most 1,000 files per repository and 10,000 per run, then produces jsDelivr, Gcore, and Fastly CDN links. Link Generator offers **Nyx managed** as the default generation method and a bounded **P2P** option; P2P carries the already selected label, amount, and filter into the bundled Nyx preset, preselects automatic repositories, and requires the user's own short-lived GitHub token in the publisher tab. Its `preset=nyx` entry loads the maintained local Nyx wrapper SVG, derives safe filenames from the Link Generator label, retains the authorized amount, and checks the published jsDelivr URLs with the selected Link Checker vendor. The user-supplied fine-grained GitHub token exists only in the current tab, is sent directly from the browser to `api.github.com`, is never sent to Nyx or written to browser storage, and requires only the repository permissions needed for the selected mode. When the optional server-only `NYX_JSDELIVR_GITHUB_TOKEN` and fixed public `NYX_JSDELIVR_GITHUB_REPOSITORY` are configured, Link Generator publishes its authorized batch directly and returns the finished jsDelivr URLs without exposing the global token; server writes are serialized to prevent branch races, use 128-bit random filename suffixes, and do not scan or impose the personal publisher's 1,000-file rollover limit on the fixed repository. Without that configuration, the personal-token handoff remains the fallback. GitHub failures must remain actionable text rather than raw markup. A one-time global Apps migration adds the publisher to an existing stored catalog without replacing unrelated owner-managed entries.
- The Apps workspace renders one shared catalog from the public same-origin `GET /api/apps` route. Built-in defaults remain in both server and client source so the workspace still opens when Firebase or the route is unavailable; a stored empty catalog is valid and must not silently restore defaults.
- Built-in Apps tiles use locally bundled full-color brand assets when a site's monochrome mark would disappear against the black workspace. Keep those assets local instead of hotlinking third-party icon hosts; the Crunchyroll, Newgrounds, Kick, and itch.io entries are the current dark-background visibility set.
- **Nyx API Keys** is a first-party app at `/apps/api-keys/`, with a local key logo in the Apps catalog and as its utility-page mark. Signed-in users can create and revoke up to five active `nyx_...` gateway keys, which are stored only as SHA-256 digests in the server-only `nyxApiKeys` collection. Newly generated plaintext is held only in its originating browser-tab session, allowing that row to reopen the copy/view control; previously generated keys cannot be recovered, so their row instead offers safe prefix copy and a replacement-key path. Revocation clears that local plaintext and removes the row from the current list immediately. The public `/api/v1/ai` endpoint accepts those keys, applies per-key minute/day limits, and proxies a restricted text-chat payload to Groq using the server-only `NYX_GROQ_API_KEY`; it must never return that provider credential or describe Nyx keys as Groq keys. The gateway fetches its permitted **chat-capable** Groq model catalog server-side and caches it briefly, falling back to configured text-model IDs if Groq is unavailable; speech, transcription, safety-only, retired, and project-inaccessible models from Groq's general model list must not reach the chat picker. Nyx AI's personal-key control accepts `nyx_...`, Navy `sk-navy-...`, and Nocturne keys; a personal key always overrides the shared provider selection. Service owners configure global providers only with server environment values (`NYX_AI_API_KEY` for the existing shared provider, `NYX_GROQ_API_KEY` for Groq, and `NYX_NAVY_API_KEY` for Navy). The browser receives only provider names, models, and responses; it must never receive a global provider credential. Regular accounts share a Firestore-backed 2,000 generated-token allowance across all of their Nyx keys per UTC day; Premium and Owner accounts have no gateway token allowance. Reservations are capped to the remaining allowance and settled against the provider-reported completion usage, with a conservative streamed-output estimate when usage metadata is unavailable. The Home utility rail exposes an **API Keys** text link at the lower right.
- The configured Founder Owner can add or remove apps for every user through **Owner Dashboard → Manage apps**. Mutations are same-origin, authenticated, Founder-only server routes under `/api/owner-dashboard/apps`, validate names and HTTP/HTTPS/Nyx/same-origin URLs, record audit events, and persist the complete ordered catalog in the server-only `nyxConfiguration/globalApps` Firestore document. Direct browser Firestore access is not the authorization boundary.
- Successful dashboard mutations update the current session immediately through `nyx:global-apps-changed`; other visible sessions refresh `/api/apps` at most one minute later. Every generated Apps surface uses the same in-memory catalog. The full Apps workspace uses a fixed four-column desktop grid that steps down to three and two columns on narrower viewports. Its tiles share Cloud Gaming's five-pixel lift, border/shadow transition, and subtle icon zoom for hover and keyboard focus, with motion disabled by the user's reduced-motion preference.

### OVH deployment

`DEPLOYMENT.md` and `deploy/` define the active single-OVHcloud-VPS deployment using Ubuntu 26.04, Caddy, systemd, authenticated Socket.IO Chat, and embedded Wisp. The installer builds the minified `dist/` output with a dynamic same-host Wisp URL and all large game assets, serves it through Express so the application IP-ban guard also covers static pages, validates and reloads Caddy, sanitizes forwarding headers, restricts Cloudflare visitor-IP trust to Cloudflare's published networks, and prunes build-only dependencies. Nyx vision runs on the VPS CPU, so the clean dependency install explicitly skips `onnxruntime-node`'s optional CUDA download; the bundled CPU runtime remains installed, while avoiding an unused GPU extraction that can exhaust the host. It installs the optional Stratus dependencies and unit separately, but enables that service only when the root-owned `/etc/nyx/stratus.env` contains a strong key. `/etc/nyx/nyx.env`, `/etc/nyx/stratus.env`, and the selected domain are preserved across reruns, and `deploy/update-ovh.sh` provides validated fast-forward updates. If a pull changes the updater itself, it re-executes the new copy before applying deployment steps so new systemd or storage requirements are not skipped on that release.

## Known Risks and Unresolved Areas

- Fast full-registry scans depend on valid paid Nocturne account credentials in the VPS environment and on Nocturne's server-side queue. Provider outages or account changes can delay that external job. Nyx can stop polling without canceling it and reconnect later, but imported verdicts remain device-local.
- Voice calls now use the authenticated OVH coturn relay when direct WebRTC connectivity fails. Keep TCP/UDP 3478 and UDP 49160-49260 allowed through every active host/provider firewall; browser-to-browser audio still requires an end-to-end call test between two real accounts and networks after changes to WebRTC, Caddy, or OVH networking.
- The search-history classifier is intentionally conservative and can still produce false positives or miss disguised harmful language. Its highlight is a moderation signal, not proof of wrongdoing. Search history is deliberately limited to explicit searches made through Nyx while signed in, retained for 30 days, and excludes destination URLs, clicked results, IP addresses, and search-engine metadata.
- Historical streamed Owner chat attachments remain on the VPS disk and are not copied to external object storage. New uploads are uniformly limited to 8 MB; keep `/var/lib/nyx/chat-attachments` available until every historical streamed attachment has been removed or migrated.
- Homepage guest presence and Chat's revision feed are intentionally local to the active single OVH Node process. A future multi-instance deployment must replace them with shared pub/sub or another realtime coordination layer before adding a second application instance.
- Cloudflare now routes `www.nyxlearning.org` to the OVH VPS. Caddy serves the apex, `www`, and `networkforteachers.netw.ar`; preserve the former Netlify target (`nyxlearning.netlify.app`) only as rollback information.
- Self-service custom domains intentionally accept only exact A/AAAA records resolving to `NYX_CUSTOM_HOST_IPS`. Certificate-authority issuance limits still apply, browser Firebase sessions are per hostname, and direct FreeDNS aliases do not inherit Cloudflare WAF protection. Keep the optional preflight rate limit, bounded authorization cache, and Caddy ask endpoint enabled.
- Spotify authentication inside the proxied browser has been unreliable. Observed failures included invalid CSRF responses and reCAPTCHA timeouts on both the custom domain and localhost. Treat it as unresolved unless a fresh end-to-end login succeeds. Do not add another forced-engine or authentication workaround without tracing the exact request/cookie/origin flow.
- Some external sites use bot protection, DRM, cross-origin isolation, OAuth restrictions, or security verification that may not work through a browser proxy. Distinguish an upstream restriction from a Nyx regression.
- Large WebGL/Unity games can still exceed a device's available GPU memory or have their own performance defects. Pirate Cove's Auto performance mode reduces host rendering and game resolution, but it cannot guarantee that every third-party game is safe on every GPU.
- Some smartwatch browsers do not expose Service Workers, so Scramjet cannot run in those browsers. Nyx reports that capability limit and offers a user-triggered direct-mode attempt for the failed tab, but sites that block iframe embedding will still be unavailable there.
- Service workers and versioned proxy assets can make old behavior appear after a deployment. Inspect the active registration and cached asset version before changing application logic.
- `script.js` and `styles.css` are large, and several feature CSS files overlap. Keep changes narrowly scoped, inspect computed precedence, and remove obsolete rules when replacing a presentation layer.
- Production is ahead of `main` until PR #34 is merged.
